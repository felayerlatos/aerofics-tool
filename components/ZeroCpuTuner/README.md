# Zero CPU 1.0

「CPU 降压超频」的独立组件。界面、控制流程、参数存储重新编写；内置 SMU 后端、VID 采样器和 y-cruncher，可独立启动。

本次交付为单个 `ZeroCpuTuner.exe`（1.0.0 打包修订 2）。第一次连接时自动展开内置组件，日常不需要手动管理 DLL。组件源码、功能分析和检查结果随包提供。

## 使用

1. Windows x64，安装 .NET 8 Desktop Runtime x64。开发机器已安装 8.0.32。
2. 运行 EXE，点击「以管理员重开」，再点击「连接 / 重新读取」。先退出其他占用同一 SMU 后端的传感器或调压窗口，避免独占锁冲突。
3. 逐核滑块、数字框、CCD 的加减按钮只修改待应用值；点击「应用 CO 并回读」才写入硬件。
4. 「自动检测并对齐」先验证每个核心的动态响应，然后从所选起始负压搜索候选，保存后显示「待 VT3」。
5. 「VT3 × 5」测试实际当前 CO，每轮 150 秒。默认只在明确计算报错时把负 CO 向 0 回调 2，然后停止，等待手动重测；启动错误、超时和取消不会被当作计算不稳定。

关闭组件会保留已经手动应用的 CO/PBO。需要撤销时使用「恢复本次连接初值」；这恢复的是本次读取值，不表示 BIOS 出厂值。「CO 全部设为 0」也只是先填入待应用值。

本组件不创建开机任务，不修改电源计划、Windows 更新、进程调度、显卡或 BIOS 设置。重启后的参数由 BIOS 和其他启动软件决定，本组件不会自动重施加。

## 功能范围

| 功能 | 行为 |
|---|---|
| 逐核 CO | -50～+10；CCD 和全核批量调整；写后连续两次精确回读 |
| VID | 原包传感器 300 ms 采样；校验包版本、时效、核心映射；不可用时显示横线 |
| 自动分核 | 起始 0～-30；每 CCD 固定参考核心；三轮基础修正上限 14/7/3，最多四轮 ±2 微调；双窗口评分并保留观察到的较好候选 |
| VT3 | 五轮 × 150 秒；明确区分计算失败、运行失败、取消和通过 |
| PBO | 相对本次初值 -800～+200 MHz；后端读取 CPU 身份、预期值、写入和回读 |
| 参数档案 | 保存实际回读值；载入 CO 到编辑区，不自动写入；PBO 在独立栏应用 |
| 恢复与诊断 | 写入前保存恢复点，取消或失败时恢复；异常退出后保留记录供手动恢复 |

自动分核支持原包的六种 LegacyCoreVid 配方：Family 19h/Model 61h 的 `540005`、`540208`，以及 Family 1Ah/Model 44h 的 `620105`、`620205`、`621102`、`621202`。其中后四种包含本机 9950X3D 所属平台的候选表布局，实际仍须表号和动态响应匹配。其他表可在后端支持时手动读取/调整，本组件不启用原版的实验性自动分核分支。

CO 的单位不是 mV；VID 接近也不等于稳定。VT3 五轮结果只对应本次参数、内存配置和负载。

## 本次检查的边界

已完成 .NET 8 Release 编译、单文件打包、内置组件展开、真实后端 help/传感器配方读取和界面布局检查。

真实 CO 读取尝试被后端返回 `This application must be run as an administrator` 拒绝。当前执行环境无管理员令牌，因此未验证真实 CO/PBO 写入、自动调校效果、VID 读数或 VT3 压力结果。此次开发没有改变当前 CPU 参数。

`validation/` 是本次实际检查结果；`analysis/` 是功能分析与传感器配方说明，不是硬件运行记录。

## 源码与构建

`source/` 为本组件可维护的 C# 源码，目标 .NET 8 Windows Forms，无第三方 UI 包。

在 PowerShell 中运行：

```powershell
cd source
.\Build.ps1
```

脚本从相邻交付 EXE 展开后端资源并重新编译。也可用 `-ExistingExe '路径\ZeroCpuTuner.exe'` 指定本次修订版 EXE。需要 .NET 8 SDK；构建过程不操作 CPU 参数。

核心文件：`TuningEngine.cs` 负责控制流程，`Infrastructure.cs` 负责 SMU 命令，`SensorSession.cs` 负责 VID 协议，`StressSession.cs` 负责负载和输出判定，`MainForm.cs` 负责界面。

运行状态位于 `%LOCALAPPDATA%\ZeroCpuTuner`。恢复记录为 `recovery.json`，本次连接初值为 `session-start.json`。不要在运行中手工编辑恢复文件。
